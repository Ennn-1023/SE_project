# Feature Specification: 老師端側邊選單導覽與題目標註逐題切換

**Feature Branch**: `006-teacher-nav-annotation-paging`

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: "修正現有UI，老師主頁設定為搶答活動，做side bar，當按下左上角三條線logo時左側彈出選單可選擇切換至搶答活動、題目管理、學生帳號與組別管理(統稱學生管理)。同時將目前teacher主頁的dev tool模擬老師搶答工具移除。修正題目標註目前新增題目會不斷疊加將頁面變得過長的問題，改為一次一題，可以用前進後退按鈕切換至別題的標註管理。"

## 背景

目前老師登入後的主頁同時放了「學生帳號建立與清單」、「組別管理」、通往「搶答活動」與「題目管理」的按鈕，以及只在開發環境出現的「模擬老師搶答操作（開發工具）」入口。老師最常用的是搶答活動，卻要先多按一下才能到達；各功能之間也沒有固定的切換方式。

題目標註畫面會把所有已標註題目的編輯區塊一次全部展開。題目一多，頁面就會變得非常長，老師要上下捲動很久才能找到要改的題目，也很難同時看到試算表格線與目前正在編輯的題目。

## Clarifications

### Session 2026-11-25

- Q: 標註改成一次一題後，要不要加題號總覽（標出有錯的題目、可點選跳題）？ → A: 要，保留總覽（US4、FR-022 維持在範圍內）。
- Q: 移除開發工具時，後端僅供開發用的模擬 API 要不要一起刪？ → A: 只刪前端入口與畫面，後端模擬 API 保留（既有搶答整合測試仍使用）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登入後直接進入搶答活動，並用側邊選單切換功能 (Priority: P1)

老師登入後，第一個看到的是「搶答活動」畫面。畫面左上角有一個三條線的選單按鈕，按下後，左側滑出選單，列出「搶答活動」、「題目管理」、「學生管理」三個項目。點選任一項目就切換到該功能的畫面，選單自動收起。

**Why this priority**: 搶答活動是老師上課時最常用的功能；固定的選單是本功能所有其他改動的基礎，學生管理也要靠它才能進入。

**Independent Test**: 以老師帳號登入，確認落在搶答活動畫面；打開選單依序點三個項目，每次都進到正確畫面，且選單收起。

**Acceptance Scenarios**:

1. **Given** 老師尚未登入，**When** 以老師帳號登入成功，**Then** 直接顯示搶答活動畫面（不再先顯示舊的老師管理頁）。
2. **Given** 老師在任一老師畫面，**When** 按下左上角三條線選單按鈕，**Then** 左側出現選單，列出「搶答活動」、「題目管理」、「學生管理」三項，且目前所在的項目有明顯標示。
3. **Given** 選單已打開，**When** 點選「題目管理」，**Then** 切換到題目管理畫面，選單收起。
4. **Given** 選單已打開，**When** 點選選單以外的區域、再按一次選單按鈕，或按下鍵盤 Esc，**Then** 選單收起且停留在原畫面。
5. **Given** 老師直接在網址列輸入老師主頁的網址，**When** 頁面載入，**Then** 顯示搶答活動畫面。
6. **Given** 老師在手機寬度的螢幕上，**When** 打開選單，**Then** 選單完整顯示、可點選，畫面不出現橫向捲軸。

---

### User Story 2 - 在「學生管理」畫面管理學生帳號與組別 (Priority: P1)

原本放在老師主頁的「建立學生帳號與學生清單」和「組別管理」移到新的「學生管理」畫面，從側邊選單進入。功能與現在相同，兩區塊的資料互相連動（例如建立學生後，組別管理中可立即選到該學生）。

**Why this priority**: 老師主頁改成搶答活動後，學生帳號與組別管理一定要有新的去處，否則功能會消失。

**Independent Test**: 從選單進入學生管理，建立一位學生、建立一個組別並把該學生加入，確認兩邊清單都即時更新。

**Acceptance Scenarios**:

1. **Given** 老師在任一老師畫面，**When** 從選單點選「學生管理」，**Then** 顯示學生帳號建立與學生清單，以及組別管理兩個區塊。
2. **Given** 老師在學生管理畫面，**When** 建立一位新學生，**Then** 不需重新整理，組別管理區塊就能選到這位學生。
3. **Given** 老師在學生管理畫面，**When** 變更組別成員，**Then** 學生清單中的組別資訊同步更新。
4. **Given** 學生帳號登入，**When** 嘗試開啟學生管理畫面的網址，**Then** 顯示「此功能僅限老師使用」的拒絕訊息，與其他老師畫面一致。

---

### User Story 3 - 題目標註一次只顯示一題，用前進／後退切換 (Priority: P1)

在題目管理的標註步驟中，題目編輯區一次只顯示「目前這一題」的內容（題號、單題／題組、共同題幹、各小題的題目格與作答格、該題的錯誤與提醒）。上方有「上一題」、「下一題」按鈕與位置提示（例如「第 3 題／共 10 題」），可切換到其他題目。新增題目時，畫面直接切到剛新增的那一題，不會再把頁面越拉越長。

**Why this priority**: 這是使用者指出的明確問題；題目一多時，現在的畫面幾乎無法使用。

**Independent Test**: 在標註步驟連續新增 10 題，確認頁面高度不隨題數增加，並可用上一題／下一題走過每一題、逐題修改格位。

**Acceptance Scenarios**:

1. **Given** 已標註 5 題、目前在第 2 題，**When** 按「下一題」，**Then** 只顯示第 3 題的編輯內容，位置提示變成「第 3 題／共 5 題」。
2. **Given** 目前在第 1 題，**Then** 「上一題」按鈕不可按；**Given** 目前在最後一題，**Then** 「下一題」按鈕不可按。
3. **Given** 已標註 4 題、目前在第 2 題，**When** 按「新增題目」，**Then** 新題目加在最後，畫面切到這一題（第 5 題／共 5 題），並進入指定題目格的步驟。
4. **Given** 已標註 10 題，**When** 依序瀏覽，**Then** 標註區塊的高度只與目前這一題的內容有關，不會因題數增加而變長。
5. **Given** 目前在第 3 題、共 5 題，**When** 刪除這一題，**Then** 畫面改顯示原本的第 4 題（現在變成第 3 題）；**When** 刪除的是最後一題，**Then** 改顯示新的最後一題；**When** 刪除後已無任何題目，**Then** 顯示「尚未標註任何題目，請按「新增題目」開始」。
6. **Given** 目前在第 2 題，**When** 按「下移」把它和第 3 題交換順序，**Then** 畫面跟著這一題移動，顯示「第 3 題／共 N 題」且內容仍是同一題。
7. **Given** 目前在第 2 題，**When** 在試算表格線上點選已屬於第 4 題的格子（未在指定格位步驟中），**Then** 選取格資訊顯示該格屬於第 4 題，並提供「前往第 4 題」的操作，按下後切到第 4 題。
8. **Given** 正在為第 2 題指定作答格（步驟進行中），**When** 按「上一題」或「下一題」，**Then** 先取消進行中的指定步驟，再切換題目，不會把格子指定到錯誤的題目。
9. **Given** 試算表格線上的角標（題1、答1、幹3 等），**Then** 仍顯示所有題目的角標，並讓目前這一題的角標比其他題更醒目。

---

### User Story 4 - 一眼看出哪些題目還有錯誤 (Priority: P2)

因為一次只顯示一題，老師需要知道其他題是否還有問題。標註區提供題目總覽（例如一排題號按鈕），有錯誤的題目以醒目樣式標示，點選題號可直接跳到該題。

**Why this priority**: 少了這個，老師要逐題翻找錯誤才能確認匯入；但沒有它，P1 的逐題切換本身仍可運作。

**Independent Test**: 標註 6 題，其中第 2、5 題故意缺作答格，確認總覽中只有這兩題標示為有錯，點題號可直接跳過去。

**Acceptance Scenarios**:

1. **Given** 第 2、5 題有錯誤，**Then** 總覽中第 2、5 題標示為有錯，其餘題目沒有標示。
2. **Given** 目前在第 1 題，**When** 在總覽點選第 5 題，**Then** 畫面切到第 5 題。
3. **Given** 修正了第 2 題的錯誤，**Then** 總覽中第 2 題的錯誤標示立即消失。
4. **Given** 有錯誤的題目，**When** 老師嘗試確認匯入，**Then** 仍與現行規則相同被擋下，且錯誤訊息指出是第幾題，老師可透過總覽前往。

---

### User Story 5 - 移除老師主頁上的開發工具入口 (Priority: P2)

老師主頁上的「模擬老師搶答操作（開發工具）」入口與它開啟的模擬畫面一併移除；側邊選單中也不會出現這個項目。

**Why this priority**: 搶答活動畫面已能完整控制活動，開發工具只會讓老師混淆；移除它不影響其他功能。

**Independent Test**: 在開發環境與正式環境以老師登入，所有老師畫面與選單中都找不到開發工具入口；直接開啟原本的開發工具網址，顯示「找不到這個頁面」。

**Acceptance Scenarios**:

1. **Given** 開發環境，老師登入，**Then** 所有老師畫面與側邊選單中都沒有「模擬老師搶答操作（開發工具）」。
2. **Given** 老師在網址列輸入原本開發工具的網址，**When** 頁面載入，**Then** 顯示「找不到這個頁面」。

---

### Edge Cases

- **舊書籤**：老師收藏了舊的老師主頁網址時，開啟後應落在搶答活動畫面；原本題目管理與搶答活動的網址仍可直接開啟。
- **進行中的活動**：老師在搶答活動進行中切換到題目管理或學生管理再回來，活動狀態不受影響，回到搶答活動畫面時顯示最新狀態。
- **標註未完成就切換**：標註進行中從選單切到其他畫面，行為與現在離開題目管理頁相同（暫存的標註草稿依現行規則保留）。
- **只有一題**：上一題與下一題按鈕都不可按，位置提示顯示「第 1 題／共 1 題」。
- **重新載入／重新開啟標註**：載入既有標註或草稿時，預設顯示第 1 題。
- **清除所有標註**：清除後顯示空狀態訊息；之後新增的第一題成為目前這一題。
- **題數上限**：已達題數上限時，「新增題目」仍與現行規則相同不可按，目前這一題不變。
- **題目很多**：總覽題號在窄螢幕自動換行，不產生橫向捲軸。
- **選單與鍵盤**：選單打開時可用 Tab 在選單項目間移動，Esc 關閉後焦點回到選單按鈕。
- **學生端**：學生畫面不顯示這個側邊選單，學生端行為完全不變。

## Requirements *(mandatory)*

### Functional Requirements

**導覽與側邊選單**

- **FR-001**: 老師登入後的預設畫面 MUST 是搶答活動畫面；開啟老師主頁網址也 MUST 顯示搶答活動畫面。
- **FR-002**: 所有老師畫面的頁首左上角 MUST 顯示三條線的選單按鈕，並帶有可被螢幕閱讀器讀出的名稱（例如「開啟選單」）。
- **FR-003**: 按下選單按鈕 MUST 從畫面左側展開選單，且選單 MUST 恰好列出「搶答活動」、「題目管理」、「學生管理」三個項目，順序如上。
- **FR-004**: 選單 MUST 標示目前所在的項目。
- **FR-005**: 點選選單項目 MUST 切換到對應畫面並收起選單；點選選單外區域、再按一次選單按鈕或按 Esc MUST 收起選單而不切換畫面。
- **FR-006**: 選單在手機寬度（至少 360 像素寬）到桌面寬度都 MUST 可完整使用，不產生橫向捲軸；選單項目的可點區域至少 44×44 像素，與現有按鈕一致。
- **FR-007**: 學生畫面 MUST NOT 顯示此選單；學生端行為不變。

**學生管理畫面**

- **FR-008**: 系統 MUST 提供「學生管理」畫面，包含現有的學生帳號建立與學生清單、組別管理兩個區塊，功能與現行相同。
- **FR-009**: 學生管理畫面中兩個區塊的資料 MUST 維持現行的互相連動（一邊變更後，另一邊不需重新整理即可看到）。
- **FR-010**: 學生管理畫面 MUST 只允許老師使用；非老師身分 MUST 顯示與其他老師畫面相同的拒絕訊息。
- **FR-011**: 原本老師主頁上通往搶答活動與題目管理的按鈕 MUST 移除，改由側邊選單提供。

**移除開發工具**

- **FR-012**: 老師端畫面 MUST NOT 再提供「模擬老師搶答操作（開發工具）」的入口或畫面，開發環境與正式環境皆然。
- **FR-013**: 開啟原本開發工具畫面的網址 MUST 顯示「找不到這個頁面」。
- **FR-013a**: 後端僅供開發與自動化測試使用的模擬 API MUST 保持不變（不在本功能移除範圍內）。

**題目標註逐題切換**

- **FR-014**: 標註區 MUST 一次只顯示一題（「目前這一題」）的完整編輯內容，包含題號、單題／題組切換、共同題幹、各小題的題目格與作答格、上移／下移／刪除，以及該題的錯誤與提醒。
- **FR-015**: 標註區 MUST 提供「上一題」、「下一題」按鈕與位置提示「第 X 題／共 N 題」；在第一題時「上一題」不可按，在最後一題時「下一題」不可按。
- **FR-016**: 按「新增題目」後，目前這一題 MUST 切換為新增的那一題，並維持現行行為，直接進入指定題目格的步驟。
- **FR-017**: 刪除目前這一題後，MUST 顯示原本排在它後面的題目；若刪除的是最後一題則顯示新的最後一題；若已無題目則顯示空狀態訊息。
- **FR-018**: 以上移／下移調整順序後，目前這一題 MUST 仍是被移動的那一題，位置提示隨之更新。
- **FR-019**: 指定格位的步驟進行中切換題目時，系統 MUST 先取消該步驟再切換，不得把格子指定給切換後的題目。
- **FR-020**: 在格線上選取已被其他題目使用的格子時，選取格資訊 MUST 提供前往那一題的操作。
- **FR-021**: 試算表格線 MUST 繼續顯示所有題目的角標，且目前這一題的角標 MUST 與其他題目在視覺上可區分。
- **FR-022**: 標註區 MUST 提供題目總覽，列出所有題目的題號，可點選直接切換，並 MUST 以明顯樣式（不只靠顏色，另加符號或文字）標示有錯誤的題目。
- **FR-023**: 載入既有標註或草稿時，目前這一題 MUST 預設為第 1 題。
- **FR-024**: 逐題切換只改變畫面呈現；標註資料內容、驗證規則、題數上限、草稿保存與確認匯入的行為 MUST 與現行相同。

### Key Entities

- **老師導覽項目**：側邊選單中的一個項目，包含顯示名稱（搶答活動／題目管理／學生管理）與對應畫面；固定三項。
- **目前這一題**：標註畫面中正在顯示與編輯的那一題，以它在題目清單中的位置表示；只存在於畫面上，不寫入試算表或資料庫。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 老師登入後不需任何額外點擊就看到搶答活動畫面；從任一老師畫面切換到另一功能最多 2 次點擊（打開選單、點選項目）。
- **SC-002**: 標註 1 題與標註 30 題時，標註區塊（不含題目總覽）的高度差距不超過 10%，即頁面長度不隨題數增加。
- **SC-003**: 在已標註 20 題的情況下，老師可在 3 次點擊內到達任一指定題目（例如透過題目總覽 1 次點擊）。
- **SC-004**: 現有學生帳號、組別、題目匯入與搶答活動功能的所有自動化測試在改版後仍全數通過（排除專為已移除開發工具畫面所寫的測試）。
- **SC-005**: 在 360 像素寬的手機畫面上，側邊選單與標註逐題切換都可完整操作，不出現橫向捲軸。
- **SC-006**: 所有老師畫面與選單中，開發工具入口出現次數為 0。

## Assumptions

- 「老師主頁」指老師登入後落地的畫面與其網址；新設計中該網址直接顯示搶答活動，題目管理與搶答活動原本的網址繼續可用，學生管理新增一個老師專用網址。
- 選單為覆蓋在畫面上的抽屜式選單（點按鈕才出現），在桌面寬度也不常駐，與使用者描述「按下才從左側彈出」一致。
- 頁首右側現有的使用者名稱、修改密碼與登出維持不變；修改密碼畫面不屬於選單三項之一，老師仍從頁首進入。
- 只移除前端的開發工具入口與畫面；後端模擬 API 依 FR-013a 保留（已於 Clarifications 確認）。
